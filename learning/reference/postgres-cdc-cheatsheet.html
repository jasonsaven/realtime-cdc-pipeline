SettingValue hereWhy
wal_levellogicalThe WAL records enough detail to decode row changes.

SHOW wal_level;

Slots

TaskSQL
CreateSELECT * FROM pg_create_logical_replication_slot('name', 'test_decoding');
Peek (bookmark stays put)SELECT * FROM pg_logical_slot_peek_changes('name', NULL, NULL);
Get (bookmark moves forward)SELECT * FROM pg_logical_slot_get_changes('name', NULL, NULL);
ListSELECT slot_name, plugin, active, restart_lsn, confirmed_flush_lsn FROM pg_replication_slots;
DropSELECT pg_drop_replication_slot('name');

Rule: drop every slot you no longer need. A slot keeps all the WAL its consumer hasn't read, even when nothing is connected.

Reading test_decoding output

    lsn    | xid |                    data
-----------+-----+--------------------------------------------------------
 0/1BDDA38 | 755 | BEGIN 755
 0/1BDDAA0 | 755 | table public.orders: INSERT: id[integer]:1 item[text]:'coffee beans' qty[integer]:2
 0/1BDDBC0 | 755 | COMMIT 755
 ...       | 757 | table public.orders: DELETE: id[integer]:1      ← key only, by default

lsn is the position in the WAL, xid is the transaction id, and each transaction is wrapped in BEGIN … COMMIT.
